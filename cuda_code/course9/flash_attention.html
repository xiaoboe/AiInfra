01 / START WITH THE PROBLEM

究竟要计算什么？

对单个 batch、单个 attention head，令 Q、K、V ∈ ℝN×d。第 r 行输出是所有 value 向量的加权和，权重由 query 与各个 key 的相似度决定。本页默认自注意力且 V 的维度同为 d；多头可在 batch/head 维上独立并行。

S = QKᵀ / √d + mask S ∈ ℝᴺˣᴺ P = softmax(S, 按行) P[r,c] = exp(S[r,c] − m[r]) / Σₖ exp(S[r,k] − m[r]) O = PV O ∈ ℝᴺˣᵈ，m[r] = max꜀ S[r,c]

先写出 N×N 的 S，再读 S 计算 P，再读 P 乘 V。即使 S/P 原地复用同一个缓冲区，也要存储一个二次规模矩阵，并产生多轮显存读写。

目录中的 self_attention_cuda 正是三段式流程，sm_o 在 Softmax 前后复用。

FlashAttention：改变计算次序

写回 O

只在片上保留当前 S/P 分块，立即消费其结果，更新输出累加器。全局内存中不需要完整的 S 或 P。它是数学等价的精确注意力算法，浮点求和顺序改变仍可能带来小误差。

优化重点是数据移动与执行组织；不会把稠密 attention 的计算复杂度变成线性。

03 / THE KEY IDEA

在线 Softmax：给历史结果换一个尺度

难点在于：只看过前几个 key 时，还不知道整行的最大值与归一化分母。如果对每块单独做 Softmax 再把输出直接相加，各块权重各自和为 1，结果就错了。

1. 定义已处理前缀的状态

m = max 已处理的分数 ℓ = Σ已处理 c exp(s꜀ − m) U = Σ已处理 c exp(s꜀ − m) · v꜀ // U 是 d 维向量 初始化：m = −∞，ℓ = 0，U = 0

U 的每一维与 ℓ 使用同一个指数尺度。任何非空前缀的注意力输出，都可以由 U / ℓ 得到。

2. 新块到来，更新最大值

m′ = max(m, max 新块 s) α = exp(m − m′) P̃꜀ = exp(s꜀ − m′) // 只计算当前块，还不是概率

如果最大值升高，历史分母与分子必须一起缩小：exp(s − m′) = exp(s − m) · exp(m − m′)。这就是 α 的来源。第一次遇到有效分数时，α = exp(−∞) = 0。

3. 重缩放历史，再加入当前块

ℓ′ = α · ℓ + Σ新块 c P̃꜀ U′ = α · U + Σ新块 c P̃꜀ · v꜀ m ← m′，ℓ ← ℓ′，U ← U′ 遍历完所有 K/V 块：O = U / ℓ

以上运算对每个 query 行独立进行；矩阵写法中 α 按行广播到 U 的 d 个维度。P̃ 也常写成未归一化的 P，本页特意用波浪号区分。

用一组数字理解重缩放

分数分两块：[1, 2] 和 [3, 0]。第一块 m = 2，ℓ = e⁻¹ + 1 ≈ 1.367879。第二块使 m′ = 3，α = e⁻¹ ≈ 0.367879。

ℓ′ = (e⁻¹ + 1)e⁻¹ + (1 + e⁻³) = e⁻² + e⁻¹ + 1 + e⁻³ ≈ 1.553002 P ≈ [0.087144, 0.236883, 0.643914, 0.032059]

取标量 V = [10, 20, 30, 40]，先得到 U = 10e⁻¹ + 20，再更新 U′ = αU + 30 + 40e⁻³，最终 O ≈ 26.209366。恰好等于完整 Softmax 后对 V 的加权和。

掩码把无效分数设为 −∞。若某一轮整行仍无有效 key，不能计算 exp(−∞ − (−∞))；应保持 ℓ = 0、U = 0。本页演示对此作显式处理。若最终整行全被屏蔽，输出约定为 0；具体框架行为需另行确认。

05 / FROM EQUATIONS TO CUDA

与 flash_attn.cu 一一对应

本目录内核名为 flash_attention_v2_kernel，体现了 Q 块并行、未归一化输出累加和最后一次除法。这是教学实现，未包含生产级 FlashAttention-2 的 Tensor Core、warp 工作划分与完整性能优化。

线程与数据索引

grid  = dim3(1, ceil(N / Br));
block = dim3(Bc, Br);

tx  = threadIdx.x;   // key 列 / d 维搬运通道
ty  = threadIdx.y;   // Q 块中的行
row = blockIdx.y * Br + ty;

// sQK[ty][tx] 对应一个分数
sQK[ty][tx] = dot(sQ[ty], sK[tx]) / sqrt(d);

当 Br = Bc = 2 时，一个 block 只有 4 个线程。tx 不表示单独的 Q 块；它在点积阶段选择 key 行，在搬运和输出阶段跨步遍历 d 维。

共享内存布局

sQ[Br][d];      sK[Bc][d];
sV[Bc][d];      sO[Br][d];
sQK[Br][Bc];    sSafeE[Br][Bc];
sMax[Br];      sDenom[Br];

若全部为 FP32，总量为 4 × (2Br·d + 2Bc·d + 2Br·Bc + 2Br) 字节。本例为 176 字节，不含编译器额外资源；真实占用还需考虑寄存器与线程块调度限制。

前向流程伪代码

这是算法级伪代码；行归约、线程协作和同步需要在 CUDA 中显式实现。

parallel for each batch, head, Q block i:
    Q_i = load(Q[i])
    m = -inf; l = 0; U = 0
    for each K/V block j:
        K_j, V_j = load(K[j]), load(V[j])
        S = Q_i @ transpose(K_j) * rsqrt(d)
        S = apply_padding_and_causal_mask(S)  // 无效项为 -inf
        m_new = maximum(m, rowmax(S))
        // 全屏蔽行用安全分支：P = 0，保留历史状态
        alpha = exp(m - m_new)
        P = exp(S - m_new[:, None])
        l = alpha * l + rowsum(P)
        U = alpha[:, None] * U + P @ V_j
        m = m_new
    O_i = U / l[:, None]  // l == 0 按约定处理
    store(O[i], O_i)
    // 若要反向传播，额外保存 LSE = m + log(l)
步骤源码中的操作需要理解的点
① 载入 QsQ[ty][i*Bc+tx]Bc 个 x 方向线程跨步覆盖 d；sO 同时清零。
② 载入 K/VsK[tx][i*Br+ty]tx 选择当前 key 行，ty 跨步搬运其特征；同步后才能共享读取。
③ 点积sQK[ty][tx] = sum * smScale每个线程沿 d 顺序累加；本实现没有使用 MMA 指令。
④ 最大值与指数localMax → newMax → sSafeE同一行所有线程各自遍历 Bc 做归约，重复工作较多。
⑤ 历史重缩放rescaleOld = exp(sMax[ty]-newMax)sDenom 与 sO 必须同时乘 rescaleOld。
⑥ 累加 PVsO += sSafeE * sVsO 此时是 U 而非归一化后的 O，每个线程更新不同 d 位置。
⑦ 写回O[...] = sO[...] / sDenom[ty]遍历所有 K/V 块后，只归一化一次。
为什么这里出现这么多 __syncthreads()？

载入共享内存后，其他线程会读取刚搬运的数据；写入分数和指数后，行归约与 PV 计算又要跨线程读取。因此必须在“生产者写完、消费者开始”之间建立同步，并在下一轮覆盖共享缓冲区前确保旧数据已被消费。

块级屏障不等于修复所有竞争。同一共享状态应由明确的线程写入，再同步广播；寄存器中的历史 m、ℓ 也应在任何线程覆盖共享状态前读取完成。多余屏障与重复归约会损失性能，需要在确认依赖后再优化。

06 / WHY IT SAVES MEMORY

二次增长的矩阵，不再需要保存

调整序列长度，比较不同结构的理论存储。以下仅计单 head：一个 FP32 N×N 中间矩阵，与 FP32 的 Q/K/V/O 四个 N×d 张量加 m、ℓ 两条行状态；固定 d = 64。两条柱子展示的是不同组成，不能当作端到端显存节省倍数。

单个 S 或 P
Q/K/V/O + 状态

公式：4N² 字节；4 × (4Nd + 2N) 字节。忽略片上 tile、梯度、优化器、分配器缓存等。Q/K/V/O 两种方法都需要；本地 Q 外层前向内核的 m、ℓ 实际驻留片上，不必全局保存两条状态。

维度普通稠密 AttentionFlashAttention
核心计算量QKᵀ 与 PV 均为 O(N²d)仍为 O(N²d)，加入在线状态操作
全局中间矩阵O(N²)，可能复用 S/P 缓冲不保存完整 S/P；只保留分块与行状态
数据移动完整 S/P 多次读写 HBM片上立即消费 tile；K/V 可能被不同 Q 块重复读取
实际速度依赖 GEMM、Softmax 与显存带宽依赖分块、精度、head 维度、硬件与并行度；教学内核不保证更快
显存容量、HBM 访问量、片上容量不是同一个概念

“线性显存”描述需要同时保存多少全局数据，不表示每个输入只被读取一次。本页 Q 外层方案有约 ⌈N/Br⌉ 个 Q 块，每块都扫描 K/V；不考虑缓存时，K/V 读入元素量约为 2⌈N/Br⌉Nd。

片上容量有限，增大 tile 可以提升数据复用，却也占用更多共享内存和寄存器，可能降低并发 block 数。实际调优要平衡数据复用、计算效率与 occupancy，不能只追求更大的块。

07 / RECOMPUTE, DON'T STORE

反向传播：用计算换掉大矩阵存储

训练需要梯度，但前向没有保存 P。可以保存每行 LSE = m + log(ℓ)，反向时重新载入 Q/K/V，按 tile 重算 S 与 P。这里忽略 dropout，mask 与前向保持一致。

Pᵢⱼ = exp(Sᵢⱼ − LSEᵢ) // 按行广播，mask 项为 0 dVⱼ += Pᵢⱼᵀ · dOᵢ dPᵢⱼ = dOᵢ · Vⱼᵀ Dᵢ = rowsum(dOᵢ ⊙ Oᵢ) // 等于 rowsum(P ⊙ dP) dSᵢⱼ = Pᵢⱼ ⊙ (dPᵢⱼ − Dᵢ) dQᵢ += (dSᵢⱼ · Kⱼ) / √d dKⱼ += (dSᵢⱼᵀ · Qᵢ) / √d

dQ、dK、dV 都需要跨相关 tile 累加；必须安排线程块的所有权与归约，避免并发写冲突。重算增加一些 FLOPs，却消除了从 HBM 读取巨大 P 矩阵的需求。本目录内核仅实现前向，以上为反向实现原理。

08 / IMPLEMENTATION NOTES

从教学版本走向可靠内核

FlashAttention-1 → FlashAttention-2

原始论文的经典算法按 K/V 外层、Q 内层描述分块与在线归一化。FA2 进一步减少非矩阵乘法操作，沿 Q 的序列维增加线程块并行，并优化 warp 间工作分配，减少共享内存通信。

本地代码采用 Q 外层与延迟归一化，但仅仅使用这两个特征，不等于已经复现完整高性能 FA2。

Causal attention 的处理

当 key 列 c > query 行 r 时，将对应分数置为 −∞。完全位于对角线上方的 tile 可以直接跳过；跨对角线 tile 仍需逐元素 mask。

交互实验实现了数值掩码，为观察过程仍遍历所有 tile。目录中的 CUDA 教学代码没有 causal mask，也没有多头与 dropout。

当前源码的适用范围与需要补齐的细节
  • 编译期 d：共享数组与索引用的是常量 dim，接口传入的 n 只参与缩放等主机逻辑；不能把它当作任意 d 的通用内核。
  • 尾块不能只做 return：Q 尾行提前退出会破坏该线程承担的协作搬运。实现通用内核时让线程继续参与协作与必要屏障，用有效位控制计算和写回。
  • K/V 尾块：当前代码只跳过超界加载，却仍用完整 Bc 个位置计算，可能读到未初始化或上一轮残留值。需要把无效 key 的分数设为 −∞，并安全处理其 V。
  • d 维尾部：i*Bc+tx 和 i*Br+ty 缺少小于 d 的判断；当前 d = 4、Br = Bc = 2 恰好整除。
  • 共享状态的所有权：同一 ty 的多个 tx 都写 sMax、sDenom，即使相同值也不应依赖这种并发写。应指定写线程，确保所有旧状态读取和消费者完成后再更新并同步。
  • 参考实现也需要检查：GEMM 中 a*sum + b*C 在 b = 0 时仍可能读取未初始化 C；若旧值是 NaN，0×NaN 仍是 NaN。应在 b = 0 时直接赋值或先初始化。
  • 资源与错误处理：测试函数使用 new[] 分配主机数组却调用 free，应配对 delete[]；所有分配、拷贝和 kernel 启动都应检查错误。这些是源码阅读提示，本页面没有修改 CUDA 文件。
建议的正确性验证与性能测量
  1. 用稳定 Softmax 的 FP64 CPU 结果作参考，检查 abs(out-ref) ≤ atol + rtol*abs(ref)；另外检查 NaN/Inf。GPU 的 FP32/FP16/BF16 需要按误差预算设置容差。
  2. 覆盖非整除 N/d、不同 tile 大小、负分数、极端 logits、重复最大值、causal 对角线与全屏蔽行。分别验证前向和反向梯度。
  3. 通过 Compute Sanitizer 的内存与竞争检测排查越界及共享内存竞争；先确保正确，再比较性能。
  4. 预热后用 CUDA Events 单独测量目标 kernel，多次运行取统计值。分开报告分配、传输和纯计算耗时；不要把普通与 Flash 两段合并计时后当成某一段的性能。
  5. 进一步考虑 MMA/Tensor Core、warp 归约、合并访存、共享内存 bank conflict、异步搬运与双缓冲。每次优化都重新校验输出。
