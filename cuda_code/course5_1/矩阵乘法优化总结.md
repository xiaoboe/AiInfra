# 矩阵乘法优化：matmul0 → matmul5

以下按**文件编号**区分版本，函数名中的编号并不连续。计算目标均为 `C = alpha * A * B + beta * C`，参数取各文件当前的启动配置。

## 版本总览

| 文件 | kernel 函数 | block 输出块 | 每块线程数 | 每线程输出数 | 核心变化 |
|---|---|---|---:|---:|---|
| [matmul0.cu](matmul0.cu) | `mysgemm_v1` | 32×32 | 1024 | 1 | 直接读取全局内存计算点积 |
| [matmul1.cu](matmul1.cu) | `mysgemm_v2` | 32×32 | 1024 | 1 | 共享内存分块复用 |
| [matmul2.cu](matmul2.cu) | `mysgemm_v4` | 128×128 | 256 | 64 | 每线程计算 8×8，增加寄存器复用 |
| [matmul3.cu](matmul3.cu) | `mysgemm_v6` | 128×128 | 256 | 64 | float4 访存、A 转置、显式寄存器片段 |
| [matmul4.cu](matmul4.cu) | `mysgemm_v7` | 128×128 | 256 | 64 | 共享内存和寄存器双缓冲流水线 |
| [matmul5.cu](matmul5.cu) | `mysgemm_warptiling` | 128×128 | 128 | 128 | 显式按 warp 划分输出和线程任务 |

## 0 → 1：把重复读取搬到共享内存

- **0 版**：每线程计算一个 C 元素，沿 K 方向直接读取 A 的一行和 B 的一列；不同线程会请求相同输入，复用主要依靠缓存。
- **1 版**：每轮协作加载 A、B 各一个 32×32 子块到 `As/Bs`，同步后从共享内存计算，再同步以防下一轮提前覆盖数据。
- **收益**：一个 A 值服务 32 列输出，一个 B 值服务 32 行输出，减少重复的全局内存读取。线程数和乘加总量不变。

## 1 → 2：每线程从一个输出改为一个输出小块

- 每线程用 `tmp[8][8]` 累加 64 个结果；256 个线程覆盖一个 128×128 输出块，K 方向每轮处理 8 个位置。
- 每轮每线程从全局内存加载 **4 个 A 值和 4 个 B 值**，供整个 block 使用。计算时读取的数据不限于自己搬来的元素。
- 固定一个 K 位置，线程需要 8 个 A 值和 8 个 B 值，组合成 64 次乘加；同一个输入参与多个输出计算。
- **收益**：更大的 block 输出块提高共享数据复用，线程内多个累加器提高寄存器复用和独立计算的数量；代价是更高的寄存器需求。

## 2 → 3：用向量化访存和转置布局减少搬运指令

- 每线程每轮仍读 **4 个 A 值和 4 个 B 值**，但由纵向分散的标量加载，改为同一行连续的 `float4` 加载。
- A 先加载到临时变量，再转置写入 `As[BK][BM]`；这样固定 K 位置所需的不同行 A 值在共享内存中连续，便于成组读取。B 保持 `Bs[BK][BN]` 布局。
- 显式把共享内存数据加载到 `a_frag[8]`、`b_frag[8]`，随后用这些值反复更新 `accum[8][8]`；输出也按 `float4` 读写。
- **收益**：减少访存指令、明确寄存器复用。每线程输出仍为 64 个，传输字节数没有因 float4 而减少；实际指令和寄存器分配取决于编译器。

## 3 → 4：提前加载下一批数据，用双缓冲隐藏等待

- `As/Bs` 各增加两套缓冲区，以 `write_index` 和 `load_index` 交替使用；共享内存占用从 8 KiB 增至 16 KiB。
- 在处理当前子块前，先发起下一子块的全局内存加载，暂存在 `ldg_a_reg/ldg_b_reg`，之后写入另一套共享内存。
- `a_frag/b_frag` 也使用两套寄存器片段：提前读取下一个 K 位置，同时用已读取的片段做乘加。
- **收益**：通过软件流水线为加载与计算重叠创造机会，减少等待；不是使用 `cp.async`，也不保证完全重叠。代价是更多共享内存、寄存器和更复杂的同步。

## 4 → 5：按 block → warp → thread 分层划分输出

- 一个 128×128 输出块由 4 个 warp 负责，每个 warp 计算 64×64；每块从 256 个线程改为 128 个线程。
- 当前 `TM=8、TN=4、WMITER=1、WNITER=4`，每线程负责 4 个 8×4 子块，共 **128 个输出**，并非只有 TM×TN 个输出。这些子块在输出矩阵中不一定连续。
- 用 `warp_row/warp_col`、warp 内线程坐标和子块迭代，明确安排共享内存读取及寄存器复用；BK 从 8 改为 16。
- **目标**：细化 warp 内的任务和数据复用布局。此版保留向量化全局访存与 A 转置，但**没有保留 4 版的双缓冲**，采用“加载 → 同步 → 计算 → 同步”的单缓冲循环，因此是另一种设计，不一定更快。

## 阅读与比较时注意

- 优化路线：**全局内存直接计算 → 共享内存复用 → 线程内多输出 → 向量化与寄存器片段 → 双缓冲 → 显式 warp 分块**。
- 比较速度必须统一矩阵尺寸、GPU、编译选项和测量方式；这些版本仍是普通 float 乘加，没有使用 Tensor Core。
- 分块版本缺少完整的边界处理，向量化访问还要求对齐；不能直接套用任意尺寸。当前 `matmul1.cu` 的 `As[ty * BK + tx]. = ...` 多了一个点，编译前需要修正；本次仅整理文档，未修改源码。
