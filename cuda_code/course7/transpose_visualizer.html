为什么交换线程任务仍然正确？

加载后 tile[r][c] = A[R+r][C+c]。线程写出时读取 tile[icol][irow]，放到 B[C+irow][R+icol]，因此正好交换行列。bidx = irow×H + icol 唯一，保证输出块内每个位置恰好被写一次。加载者和写出者可以是不同线程，同步建立先后关系。

展开版为什么写 out[to + ny × 32]？

第二份输入在第一份右边 32 列；转置后位于第一份下边 32 行。输出一行有 ny 个元素，所以下移 32 行的地址增量为 ny×32。补齐列仅改变共享内存跨度，不改变全局矩阵形状。

怎么解读 benchmark？

输入为 4096×4096 float，5 次预热后计时 5 次 kernel，输出平均耗时；数据上传与下载均在计时区间之外。当前 main 只运行展开版。有效带宽 = 2×nx×ny×4 / (平均毫秒数×10⁶) GB/s。源码未逐元素校验输出，也没有记录可供此页面展示的性能数据。

源码适用范围：本演示使用完整块。原共享版本的边缘块条件与同步需要修正；Unpad 版本还把输出的 nx/ny 边界写反；展开版的 grid 整数除法可能漏掉尾列。4096 方阵掩盖了这些问题。通用实现应分别判断输入、输出边界，并让所有线程无条件到达 __syncthreads()。详见 Markdown 第 7 节。
